# terraform-mikrotik-wireguard

[![Latest Release](https://img.shields.io/github/v/release/eanselmi/terraform-mikrotik-wireguard.svg)](https://github.com/eanselmi/terraform-mikrotik-wireguard/releases/latest)

Terraform module to run a **WireGuard server on MikroTik RouterOS 7**, with **per-user access control** enforced in the router firewall.

Its goal is **least privilege**: every user declares the destinations they are allowed to reach, and everything else is denied. A client's `AllowedIPs` is only routing and the user can edit it, so the actual authorization lives on the router — not on the laptop.

## How it works

Each user gets an address list with their permitted destinations and an `accept` rule in a dedicated chain, closed by a default `drop`:

```
forward ──jump (in-interface=wgX, src=tunnel_subnet)──> chain "wireguard"
                                                          ├── accept  src=IP_user1  dst-address-list=wg-user1
                                                          ├── accept  src=IP_user2  dst-address-list=wg-user2
                                                          └── drop    src=tunnel_subnet   (logged)
```

Resources created:

- **One WireGuard interface** with a fixed listen port, plus its tunnel IP address.
- **One peer per user**, each with its own key pair, generated by the module.
- **One address list per user**, with one entry per allowed destination. Entries accept IPs, CIDRs or FQDNs — RouterOS resolves names dynamically.
- **Firewall rules**: an `accept` per user in its own chain, a scoped default `drop`, the `jump` from `forward`, and the `accept` for the UDP port in `input`.
- **A srcnat masquerade** for the tunnel subnet, optional.
- **One client configuration file per user**, optional.

Adding a user is a map entry. Removing one deletes their peer, address list, firewall rule and configuration file.

## Router prerequisites

**1. A transport for Terraform.** Enable either `api-ssl` (8729) or the REST API (`www-ssl`), which needs a certificate. On RouterOS 7.24 a direct self-sign fails with `CA not found`, so create a CA first:

```routeros
/certificate add name=ca-tpl common-name=MY-CA key-usage=key-cert-sign,crl-sign days-valid=3650
/certificate sign ca-tpl name=my-ca
/certificate add name=api-tpl common-name=10.0.0.1 days-valid=3650 key-size=2048 \
    key-usage=digital-signature,key-encipherment,tls-server
/certificate sign api-tpl ca=my-ca name=api-cert
/ip service set api-ssl certificate=api-cert address=10.0.0.0/24 disabled=no
```

**2. A dedicated user** with the `api`, `read`, `write` and **`sensitive`** policies. Without `sensitive` the user cannot read private keys and every plan shows a phantom change on `private_key`.

```routeros
/user group add name=terraform policy=api,read,write,sensitive
/user add name=terraform group=terraform password=<secret> address=10.0.0.0/24
```

**3. `/ip dns` configured**, if any `endpoints` entry is an FQDN.

**4. The UDP port open** on whatever network firewall sits in front of the router.

## Usage

Reference the module from the Terraform Registry:

```hcl
provider "routeros" {
  hosturl  = "apis://10.0.0.1:8729"
  username = var.router_user
  password = var.router_password
  insecure = true # self-signed certificate
}

module "wireguard" {
  source  = "eanselmi/wireguard/mikrotik"
  version = "1.0.1" # optional; omit to use the latest release

  interface_name = "wg0"
  listen_port    = 51820
  tunnel_subnet  = "172.19.1.0/24"

  client_endpoint    = "vpn.example.com:51820"
  client_allowed_ips = ["10.0.0.0/16"]
  client_config_path = "${path.root}/config_files"

  # Without these the rules land at the end of their chains — that is,
  # after the default drop and after any existing srcnat rule.
  input_place_before_comment  = "Default Drop"
  srcnat_place_before_comment = "Generic NAT"

  users = var.users
}
```

…or from a local path:

```hcl
module "wireguard" {
  source = "../../modules/mikrotik-wireguard"

  tunnel_subnet      = "172.19.1.0/24"
  client_endpoint    = "vpn.example.com:51820"
  client_allowed_ips = ["10.0.0.0/16"]
  users              = var.users
}
```

## Inputs

| Name                        | Description                                                                       | Type                | Default                 | Required |
| --------------------------- | --------------------------------------------------------------------------------- | ------------------- | ----------------------- | :------: |
| users                       | Users of the tunnel — see the table below                                          | `map(object)`       | n/a                     |  **yes** |
| tunnel_subnet               | Tunnel subnet in CIDR notation. Scopes the jump, the drop and the masquerade       | `string`            | n/a                     |  **yes** |
| client_allowed_ips          | Networks the clients route through the tunnel (`AllowedIPs`), the same for everyone | `list(string)`      | n/a                     |  **yes** |
| client_endpoint             | Endpoint the clients connect to, `host:port`                                       | `string`            | n/a                     |  **yes** |
| interface_name              | Name of the WireGuard interface. Changing it recreates the interface               | `string`            | `"wg0"`                 |    no    |
| listen_port                 | UDP port the interface listens on                                                  | `number`            | `51820`                 |    no    |
| router_address              | Router's own IP inside the tunnel, no mask                                         | `string`            | first host of the subnet |    no    |
| server_mtu                  | Interface MTU. `null` keeps the RouterOS default                                   | `number`            | `null`                  |    no    |
| firewall_chain              | Chain holding the per-user rules                                                   | `string`            | `"wireguard"`           |    no    |
| address_list_prefix         | Prefix of the per-user address lists                                               | `string`            | `"wg-"`                 |    no    |
| input_place_before_comment  | Comment of the `input` rule to insert the port `accept` before                     | `string`            | `null`                  |    no    |
| srcnat_place_before_comment | Comment of the `srcnat` rule to insert the masquerade before                       | `string`            | `null`                  |    no    |
| create_nat_masquerade       | Create the srcnat masquerade for the tunnel subnet                                 | `bool`              | `true`                  |    no    |
| log_dropped                 | Log traffic hitting the default drop                                               | `bool`              | `true`                  |    no    |
| drop_log_prefix             | Log prefix for the default drop                                                    | `string`            | `"DROP-WG"`             |    no    |
| comment                     | Comment applied to every object created on the router                              | `string`            | `"Managed by Terraform"` |    no    |
| client_keepalive            | `PersistentKeepalive`, in seconds, for the client configurations                   | `number`            | `25`                    |    no    |
| default_client_dns          | DNS for users that do not define their own                                         | `string`            | `"1.1.1.1"`             |    no    |
| client_config_path          | Directory to write the `.conf` files into. `null` writes nothing                   | `string`            | `null`                  |    no    |

### User map entry

Each key in `users` is the peer name; its value is an object with these attributes:

| Attribute   | Description                                                                                      | Required |
| ----------- | ------------------------------------------------------------------------------------------------ | :------: |
| `ip`        | Tunnel IP for the user, unique, inside `tunnel_subnet`, written without a mask                    |  **yes** |
| `endpoints` | Destinations this user is allowed to reach — IPs, CIDRs or FQDNs                                  |  **yes** |
| `dns`       | DNS for this user's client configuration. Falls back to `default_client_dns`                      |    no    |

## Outputs

| Name               | Description                                             |
| ------------------ | ------------------------------------------------------- |
| client_configs     | Ready-to-hand-out configuration per user (**sensitive**) |
| server_public_key  | Public key of the router's interface                     |
| interface_name     | Name of the created interface                            |
| listen_port        | UDP port the interface listens on                        |
| router_address     | Router's IP inside the tunnel                            |
| peer_public_keys   | Public key of each user                                  |

## Example

Two users on the same tunnel, with different permissions: one reaches a whole subnet and an internal API by name, the other only a single host and uses an internal DNS server.

```hcl
users = {
  jdoe = {
    ip        = "172.19.1.10"
    endpoints = ["10.0.5.0/24", "api.internal.example.com"]
  }
  asmith = {
    ip        = "172.19.1.11"
    endpoints = ["10.0.5.10"]
    dns       = "10.0.0.53"
  }
}
```

Both clients receive the same `AllowedIPs`, so both route `10.0.0.0/16` into the tunnel. If `asmith` tries to reach `10.0.5.20`, the packet arrives at the router and hits the default drop:

```
firewall,info DROP-WG forward: in:wg0 out:ether1, src-mac ..., proto TCP (SYN), 172.19.1.11:51324->10.0.5.20:443, len 60
```

## Client configuration files

When `client_config_path` is set, the module writes one `<user>.conf` per user with `0600` permissions, ready to import into any WireGuard client:

```ini
[Interface]
PrivateKey = <generated by the module>
Address = 172.19.1.10/32
DNS = 1.1.1.1

[Peer]
PublicKey = <interface public key>
AllowedIPs = 10.0.0.0/16
Endpoint = vpn.example.com:51820
PersistentKeepalive = 25
```

Removing a user from the map deletes their file on the next apply. Use a path relative to `path.root`, not to the module.

> **These files contain private keys.** Keep the directory out of version control and treat it as secret material. The same applies to the `client_configs` output.

## Notes & caveats

- **Private keys end up in the state.** The module generates the key pairs, so the state must be treated as sensitive material: remote backend, encryption at rest and restricted access.
- **`client_allowed_address` cannot be set.** The field exists in RouterOS 7.21+ but the provider does not expose it ([issue #966](https://github.com/terraform-routeros/terraform-provider-routeros/issues/966)), so the Client Config the router generates has no `AllowedIPs`. Hand out the `.conf` files instead of the router's QR code. Because the router does return the field when reading a peer, every plan and apply emits one harmless warning per user: `Field 'client_allowed_address' not found in the schema`. There is no way to silence it from the provider.
- **`routeros_ip_address` cannot be updated in place.** The provider includes `vrf` in every update payload and RouterOS 7.24 rejects it with `unknown parameter vrf`. The module ignores `comment` changes on that resource so a change to `var.comment` cannot leave the stack unable to converge. To actually change it, recreate the resource — which leaves the interface without an IP for a moment: `terraform apply -replace='module.wireguard.routeros_ip_address.this'`.
- **`place_before` is resolved by comment.** If the anchor rule is renamed or deleted on the router, the plan fails because it cannot be found. That is deliberate: an error is better than silently inserting a rule where it has no effect. Leave the variables at `null` only if the end of the chain is a valid position.
- **Host masks are normalized.** RouterOS stores a `/32` as a bare IP, which is why the per-user rules use no mask. The peer's `allowed_address` does keep it.
- **Pin the listen port.** When a WireGuard interface is recreated by hand, RouterOS assigns a random port. The symptom is a tunnel that never completes a handshake, with `Rx = 0 B`. This module sets the port explicitly, so any drift shows up in the plan.
